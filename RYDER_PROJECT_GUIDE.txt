📋 PROJECT OVERVIEW
================================================================================
RYDER is a Next.js vehicle booking platform with authentication, modal-based 
forms, and Redux state management. Think of it like a smart Uber-like app where 
users can book vehicles.

Tech Stack:
- Next.js 16.2.4 (App Router)
- React 19.2.4
- TypeScript 5
- Tailwind CSS v4
- NextAuth v5 (Authentication)
- Redux Toolkit (State Management)
- MongoDB (Database)
- Framer Motion (Animations)

🔐 AUTHENTICATION FLOW (Login/Signup Journey)
================================================================================

STEP 1: User Opens Login Modal
────────────────────────────────
What happens: User clicks "Sign In" button in Header → Redux dispatches 
openModal() + setFormType('login') → Modal appears on screen.

STEP 2: User Fills Login Form
──────────────────────────────
What happens: User enters email/password → clicks "Sign in" → form data sent 
to doLogin server action via useActionState.

STEP 3: Server Validates Credentials
─────────────────────────────────────
What happens: login.ts server action receives FormData → validates fields → 
calls NextAuth signIn('credentials') → checks database for matching user.

STEP 4: NextAuth Creates Session
─────────────────────────────────
What happens: If credentials valid → NextAuth creates encrypted JWT session → 
stores session in HTTP-only cookie → returns success to client.

STEP 5: Client Updates Session
───────────────────────────────
What happens: Login component receives success → calls update() from NextAuth → 
triggers session re-validation → all useSession() hooks detect change.

STEP 6: InitUser Fetches User Data
───────────────────────────────────
What happens: InitUser.ts component detects status === "authenticated" → calls 
useMe hook → fetches /api/auth/me endpoint → receives full user object from 
database.

STEP 7: Redux Store Updates
────────────────────────────
What happens: useMe hook dispatches setUserData(userResponse) → Redux userSlice 
updates userData field → all components subscribed to selectUser re-render.

STEP 8: Header Shows User Profile
──────────────────────────────────
What happens: Header's useSelector(selectUser) gets new userData → conditional 
rendering switches from "Sign In" buttons to user avatar + "Drive with us" button.

STEP 9: Modal Closes Automatically
───────────────────────────────────
What happens: Login component's useEffect detects success → calls onClose() 
after 500ms → Redux dispatches closeModal() → AuthForm unmounts.

🚪 LOGOUT FLOW
================================================================================

Flow Diagram:
[User clicks Logout] → [signOut redirect:false] → [NextAuth destroys session] 
→ [Session status = unauthenticated] → [Header useEffect detects change] 
→ [dispatch setUserData null] → [Redux clears userData] 
→ [Header shows Sign In buttons]

STEP 1: User Clicks Logout
───────────────────────────
What happens: User clicks avatar → logout dropdown appears → clicks "Logout" → 
handleLogout() function executes.

STEP 2: NextAuth Destroys Session
──────────────────────────────────
What happens: signOut({redirect: false}) called → NextAuth deletes session 
cookie → marks session as invalid on server.

STEP 3: Session Status Changes
───────────────────────────────
What happens: NextAuth broadcasts status change → all useSession() hooks receive 
status: "unauthenticated" → React triggers re-renders.

STEP 4: Header Clears Redux
────────────────────────────
What happens: Header's useEffect detects status === "unauthenticated" → 
dispatches setUserData(null) → Redux userSlice resets to initialState.

STEP 5: UI Updates Instantly
─────────────────────────────
What happens: selectUser selector returns null → Header conditional rendering 
switches back to login/register buttons → no page refresh needed.

📝 REGISTRATION FLOW
================================================================================

STEP 1: User Opens Register Modal
──────────────────────────────────
What happens: User clicks "Start your journey" → Redux dispatches 
setFormType('register') + openModal() → RegisterForm component renders inside 
modal.

STEP 2: User Submits Registration
──────────────────────────────────
What happens: User fills name/email/password → form submits to doRegister server 
action → server validates with Zod schema.

STEP 3: Server Creates User
────────────────────────────
What happens: register.ts hashes password with bcrypt → creates user in MongoDB → 
generates 6-digit OTP → sends email via Nodemailer/Gmail SMTP.

STEP 4: Client Switches to OTP Form
────────────────────────────────────
What happens: Register component receives success → dispatches setEmail(email) 
to Redux → dispatches setFormType('otp') → OTP component replaces RegisterForm.

STEP 5: User Enters OTP
────────────────────────
What happens: User checks email → enters 6-digit code → submits to verification 
endpoint → server compares OTP with database value.

STEP 6: Account Activated
──────────────────────────
What happens: If OTP matches → server updates isVerified: true → returns 
success → client shows success toast → modal closes → user can now login.

STEP 1: Store Initialization
─────────────────────────────
What happens: appStore.ts creates Redux store with modalSlice + userSlice → 
Providers wraps app with <Provider store={store}> → store available globally.

STEP 2: Modal State Changes
────────────────────────────
What happens: User clicks button → dispatch openModal() → modalSlice sets 
isModalOpen: true → AuthForm component renders → modal overlay appears.

STEP 3: Form Type Switching
────────────────────────────
What happens: User clicks "Sign up" link → dispatch setFormType('register') → 
modalSlice updates formType → AuthForm conditionally renders RegisterForm 
instead of Login.

STEP 4: User Data Sync
───────────────────────
What happens: useMe hook fetches user → dispatch setUserData(response) → 
userSlice updates userData → Header/other components read via 
useSelector(selectUser).

STEP 5: State Cleanup
──────────────────────
What happens: Modal closes → useEffect detects !isModalOpen → dispatch 
setFormType('login') → resets formType for next open → prevents stale state.

💡 PRO TIPS FOR BEGINNERS
================================================================================

1. Session vs Redux:
   NextAuth session = "are you logged in?"
   Redux userData = "who are you?"

2. Server Actions:
   Always return plain objects, never Response objects from server actions

3. useEffect Dependencies:
   Missing dependencies = stale data
   Too many dependencies = infinite loops

4. Modal State:
   Always reset formType when modal closes to prevent showing wrong form 
   next time

5. Session Updates:
   Call update() after login to trigger re-validation across all components

6. Error Handling in Server Actions:
   When catching errors of type 'unknown', cast to minimal interface like 
   { type?: string } instead of using @ts-ignore to preserve type safety

7. Fetch URL Construction:
   Use new URL() with base URL to avoid "Invalid URL" errors in server actions

8. API Response Format:
   Always return message as string, not object, to prevent React rendering errors

🚀 HOW TO RUN THE PROJECT

1. Install dependencies:
   npm install

2. Set up environment variables (.env):

   - NEXTAUTH_SECRET=your_secret_key

3. Start development server:
   npm run dev

4. Open browser:
   http://localhost:3000

🐛 COMMON ISSUES & SOLUTIONS
================================================================================

Issue: "Invalid URL" error in server action
Solution: Use new URL('/api/endpoint', process.env.NEXT_PUBLIC_APP_URL)

Issue: Modal shows wrong form after closing
Solution: Reset formType to 'login' in useEffect when isModalOpen becomes false

Issue: UI doesn't update after login/logout
Solution: Call update() after login, listen to session status changes

Issue: "Cannot update a component while rendering" error
Solution: Move dispatch/setState calls into useEffect or event handlers

Issue: TypeScript error "Property 'type' does not exist on type 'unknown'"
Solution: Cast error to interface: const error = e as { type?: string }

Issue: Gmail SMTP authentication fails
Solution: Use App Password (not regular password), remove all spaces

📚 GLOSSARY FOR BEGINNERS
================================================================================

Server Action: A function marked with "use server" that runs on the server 
instead of the browser. Safe for database operations.

Session: A way to remember that a user is logged in. Stored as an encrypted 
cookie.

Redux: A library for managing global application state. Think of it as a 
central storage that any component can access.

Dispatch: The action of sending a command to Redux to change the state.

Selector: A function that extracts specific data from the Redux store.

useEffect: A React hook that runs side effects (like fetching data) after 
component renders.

Hook: A special React function that lets you use React features (like state) 
in functional components.

Modal: A popup window that appears on top of the main content.

Provider: A React component that makes a library (like Redux) available to 
all child components.

Slice: A piece of Redux state that handles a specific feature (like modals 
or user data).
